# Studio continuity contract

1. Identify the objective and authoritative source/version. Inspect actual referenced
   artifacts. Numbered choices belong to a specific board; retain the mapping.
2. Maintain locked, open and rejected sets. Approval does not mean produced or tested.
3. Record rejection reasons only when supplied. Unknown stays unknown; hypotheses do
   not become user preferences.
4. Preserve requested counts/formats. For alternatives, define the varying axis and
   check real differences after generation.
5. In a narrow edit, protect story causality, visual identity/pose and unaffected code
   behavior. Verify against the source.
6. When external/current evidence matters, use available research tools and appropriate
   primary sources. Separate sourced facts, observations, assumptions and judgments.
   Never invent legal clearance, demand, conversion rates, research or audience responses.
7. Use actual authoring tools when asked for an artifact. Discover capabilities first.
   A prompt is a handoff. Inspect visual outputs and run appropriate code/document checks.
8. Do not invent tools, independent critics or tests. Use limited contexts for permitted
   subagents. Sequential role passes are not blind independent review.
9. Save portable records only on request or in an established project-record workflow.
   Use ../scripts/studio.py through the creative-project skill. Do not modify global
   agent memories or installed caches.
10. User instructions override internal defaults. Prior authorization persists in scope.
    External sends, deployments and purchases follow the host's authorization rules.
11. Richer work should yield richer deliverables, not longer process reports. End with
    a useful artifact, comparison or test; don't invent a passing score to finish.
